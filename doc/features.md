# 功能细节

## 语音：前台按住说话，后台连续听

**鸭子可见（前台）**：按住屏幕 ≥250 ms 开麦，松开让识别器把这半句交出来（识别结束才用，
中间结果不开）；短按不开麦，防手滑。

**鸭子看不见（后台）**：退到后台时切成**连续听**，并由 `DuckService` 这个前台服务把麦克风
握在手里（`foregroundServiceType="microphone"`，通知栏里一条「鸭子醒着」，点它回应用就停）。
后台没有人能按住屏幕，所以只有这一种可能。

为什么前台不做成"一直在听"：不说话时识别器几秒就超时结束一次，要接着听得立刻重挂 → 每
6.2 秒一轮、系统的录音提示音一直响、麦克风一直占着（§5、§13）。**这个代价在后台照单全收**
—— 后台连续听的实测间隔是 5.2 秒一轮（模拟器，每轮 logcat 里都打出来），它只是不再发生在
用户盯着鸭子看的时候了。

两个实现上的坑：识别器**秒回**（识别服务不可用，模拟器上就是错误码 2）要**退避**，不退避就是
每秒重挂五次的空转 —— 一轮短于 1 秒就翻倍等，最长 5 秒。还有，打开自己的日志页也会让
MainActivity `onPause`，那不是"退到后台"：那种情况按老样子把麦关掉，别在看日志的时候开着麦。

识别结果先过**静音窗口**：鸭子说话期间 + 说完 800 ms 之内一律丢弃 —— 不堵的话喇叭的声音会被
麦克风听回去、识别成一句话再送去云端，就是自激回环。连续听也照过这道闸。

## 识别器是谁：一个可换的端口（`core/Stt.kt`）

**"本机识别"里的"本机"由设备决定，不由我们决定。** Android 的 `SpeechRecognizer` 自己不识别，
它只是绑到设备上另一个 app 的 `RecognitionService`；AOSP 不带识别器。GMS 机器上默认那个是
Google 的（识别在它服务器上做），国行 ROM 上一般是厂商的（传到厂商服务器）。

所以这块做成了可替换的：`SttSource` 是端口，`VoiceInput` 只是驱动（排队、静音窗口、连续听的
退避、前台上后台的切法），换个识别服务 = 再写一个 `SttSource`。

- **挑源**：`chooseStt` —— **端上优先于云**（这条是隐私，不是性能），都没有就关掉语音输入。
- **如实标注**：每个源自己报 `onDevice`（音频出不出手机），logcat 里 `识别源：…` 会写明
  "音频不出手机"还是"音频会传到它那边"。**别为了好听把它写成 true。**
- **换源**：某个源被判死刑（`fatalForSource`：12 中文不支持 / 13 语言包没下）时换下一个，
  并且**拉黑它** —— 不拉黑的话两个源都坏时会来回换，换到天荒地老（模拟器上真演了一遍：
  on-device 报 12 → 换 system → system 报 12 → …）。没得换就把语音输入关掉，别装作还能听。
- 实测（模拟器）：挑中 on-device → 报 12（模拟器的端上识别没有中文包）→ 换 system →
  报 2（网络不通，非死刑，不换源）。

**音频去哪儿**：我们不把音频发给云端模型（发过去的只有文字）；但**退到系统/厂商识别时，
音频会到他们那边** —— 这句话以前在 README 里写成"音频不上传"，是不准的。

## 相机：每 2 秒一拍 + 本机检测器

`CameraSense` 用 Camera2 + `ImageReader`（640×480 JPEG）取帧，主线程每 2 秒把一拍丢给 agent 线程。
认图在 **agent 线程**上做（模型跑一次几十毫秒，一拍 2 秒，不另开线程），用的是 ML Kit 的
image labeling **bundled 版**：模型 2.9 MB 跟着 APK 走，不下载、不联网，像素也不出这台手机。
认出来的东西写成一句话交给云端 —— 发出去的是标签（"看到 人、椅子"），**不是图**。

- 阈值和取几个在 `core/Detector.kt`（纯逻辑，可单测）：低于 **0.6** 的不说，最多说 **3** 个，
  按分数排序。都没有就是 `摄像头正常，未识别物体`。
- **这句话里没有置信度**。踩过：带上百分号之后，同一幅画面每拍给出的分数都在抖
  （实测 77% / 73% / 71% / 73%），文字一变就写一条新事件，去重等于失效 —— 事件流和 logcat
  会被同一幅画面灌满。分数只用来决定谁进得了这句话。
- 标签是英文的，`labelName` 把常见的翻成中文（人/狗/椅子…），**没收录的原样返回英文** ——
  模型读得懂，比自己编一个不准的词好。
- **文字没变化就不写事件**（也就不打日志，闲着的 logcat 是干净的）。
- 用了 bundled 版就得管 ABI：它的 `libmlkitcommonpipeline.so` 按 4 个 ABI 各打一份（合计 40 MB），
  所以 `ndk.abiFilters` 只留 `arm64-v8a`（debug APK 67 MB → 37 MB）。

**为什么不走 Play 服务那个版本**（`play-services-mlkit-image-labeling`，APK 只涨两三兆）：
模型要现下，实测**带 Play 服务的模拟器都下不动**，国内真机更没戏。见 `doc/gotchas.md`。

距离用听筒旁边那个**接近传感器**：它只有"挡住 / 没挡住"，量程之外什么都看不见（远端读数就等于
量程，通常 5 cm）。所以只有**读数小于量程**才算"前方有东西"、才拼上"最近距离 0 米" ——
盖住听筒时近距离拒绝会生效，鸭子不肯往前走。按原样把 5 cm 报成"最近距离 0.05 米"的话，
真机上一切前进动作都会被挡掉。

图片只在手机上：`seen/latest.jpg`（调试面板的「拍一张」按需更新），**不上传**。

## 云端

OpenAI 兼容（默认 DeepSeek）。请求体只有 `model` / `messages` / `max_tokens` / `stream` ——
没有 `conversation_id`、没有媒体字节、没有关节角。SSE 逐块读，socket 的 `readTimeout` 设成
8 秒就是"8 秒没有下一个 token 抛异常"（每读到一块就重置）；**连接阶段**失败才重试 1 次，
读数据阶段的超时不重试。

`local.properties` 里没填 key 就退回演示用的假大脑（`ScriptedCloud`），没网也能跑。

**key 分两个属性**：`duck.apiKey` 只进 debug 包，`duck.releaseApiKey` 只进 release 包
（默认空）。key 是明文编进 `BuildConfig` 的，所以 release 那个默认不留 —— 编出来的 release 包
不含任何 key，拿给谁都不会漏。验证过：`unzip -p app-release-unsigned.apk 'classes*.dex' |
grep -a -o 'sk-.\{20,\}'` 是 0 处，debug 包是 1 处。

logcat：`duck-cloud` 打端点、每轮发出的条数/字节数、模型的原话、失败原因；`duck-say` 打鸭子说的
每一句话。

## 调试面板与打字输入（只在 debug 构建）

规格里屏幕是一整块 WebView、没有控件，所以这些只在 debug 里挂：

- **右上角一列按钮**：站 / 坐 / 看左 / 看右 / 走一步 / 退一步 / 停 / 说 直接驱动 `RobotPort`
  （不写事件、不走 agent 循环）；「拍一张」存一帧；「视角」换 8 个机位；「跳舞」；「日志」；
  「下一句台词」走整条链。按了往 logcat 打一条 `duck-panel`。
- **底部打字输入**：打一句、回车或点发送，走的是 `onTyped` —— 和语音同一条链（排队、busy、
  短句只记不推理都一样），只是事件记成 `text`、意图里写「打字：xxx」。没打过字的时候意图里
  不出现「打字」那一块，说话那条链的意图和 §3.3 原样一样。

## 跳舞

《哈基米》（赛马娘那段蜂蜜之歌的二创）**122 BPM**，一拍 492 ms，八拍 3.936 s 一循环，
曲子 24.3 s 正好跳 6 轮。动作照"帝皇舞步"那个感觉编：原地高抬腿踏步、左右倾、点头、跟拍张嘴，
身体还带一点横移和扭腰 —— 这只鸭子能动的只有两条腿、头和嘴。

- 舞步数据在 `core/Dance.kt` 的 `hakimiDance()`，一张八拍表，改舞只改这里；
  抬腿/屈膝的方向拿 `SIT` 那组角度当基准校过，倾斜/点头的方向是一张张渲染出来看的。
- 再按一次「跳舞」或按「停」收舞；曲子放完自动收，收舞时 250 ms 混回站立
  （不然会从一个半空姿势"啪"地跳回去）。

## 日志页

调试面板上按「日志」。数据全部读 `filesDir/agent/` 下已落盘的文件，所以重启后照样能翻：

| 页签 | 看什么 |
|---|---|
| **上下文** | `pack(transcript)` 的原样 —— 这一轮真会发出去的消息（系统提示词 + 记忆块 + 轨迹）。**图片不在里面**（不上传媒体），图片单独在「事件」看 |
| **事件** | `episodes.jsonl` 原始流（听到 / 看到 / 做过 + 时间 + id），最上面是最近留存的那一帧 |
| **轨迹** | `transcript.json` 的消息 + 上一段轨迹的摘要 + 归档条数和各文件大小 |

用 Compose 写的（`compose-bom 2023.10.01` + `activity-compose 1.8.1`，Kotlin 1.9.20 配编译器
1.5.4）—— 代价是 debug APK 从 4.1 MB 涨到约 19 MB（没开混淆）。要瘦下来就在 release 上开
`minifyEnabled true`，或者把这个页面挪出主包。

## 记忆与轨迹

- 听到 / 打字 / 看到 / 做过各写一行 `episodes.jsonl`（读盘只取尾部 2000 条）。
- 每次要发给云端之前，用当前这句话去检索：中文按字切、英文数字按词切，按重合度和时间打分，
  每类取最相关的几条拼成「意图」。
- 轨迹（`transcript.json`）在变长之后会压缩：老的几条交给云端汇成一段摘要，原文挪到
  `transcript-archive.jsonl`，之后只带摘要 + 最近几条。**本轮的 user 意图不参与切割**
  —— 一轮里 tool 往返会把消息推过 keep-6 条，光 `takeLast(6)` 会把用户问的那句摘要掉，
  模型从第 7 条起就看不到问题了。压出来的摘要先拿到手、再归档，压缩那次调用失败就当这轮不压缩
  （异常不能穿出 `onHeard`）。

## Android 侧的三件事

- **屏幕常亮**已加（`FLAG_KEEP_SCREEN_ON`）。Activity 进后台时 Choreographer 会停，鸭子停步。
- **麦克风的前台服务**（`DuckService`）：`foregroundServiceType="microphone"` +
  一条常驻通知 + `POST_NOTIFICATIONS`（Android 13+，**manifest 里必须声明**，只写运行时请求
  的话 `pm grant` 会报 "has not requested permission"）。服务在 `onPause` 里起 ——
  Android 12 起不允许从后台启动前台服务，`onPause` 那一刻还算前台，`onStop` 就晚了。
- 音量下键的演示触发已经删掉（语音接上之后不再占着音量键）；长按屏幕现在是"按住说话"。
